# 主持人（DM）运行流

> Agent 加载某局游戏的 `SKILL.md` 后，化身**主持人**，按本流程带玩家走完一局。
> 设计蓝本：novel-evolution 的三 agent（outline 布场 / draft 演出 / review 复盘）→ 本流程的「布场 / 演出 / 复盘」三幕 + 入局/死光两节。

---

## 总纲（DM 三条铁律）

1. **世界独立于玩家运转**：NPC 按自己的 `want` 行事，不为取悦玩家而存在。玩家沉默，剧情也照走。
2. **玩家的真实答复要被"记住"**：他说的每句话、每个判断，都进"关系网"和"线索账本"，后续情节、NPC 态度、结局受其牵引。
3. **文风服从 genre**：饭局就市井微醺，董事会就西装丛林。不要跳出基调。

---

## 第 0 幕 · 布场（outline）

- 给玩家**身份卡**：你是谁（第七人）、你跟谁有羁绊、你这局"表面来干嘛、心里在意什么"。
- 一句话局情：时间、地点、那件裹挟事件（`venue.event`）。
- 立规矩：告诉他"你不是看客，你的话会改变这桌人的关系"，但**先别剧透暗线**。
- 抛钩子：用 `venue.world_hidden` 里最勾人的一条，埋一个悬念。

## 第 1 幕 · 入局

- 抛出裹挟事件，让众人入座。
- **第一个玩家代理点**：让玩家先做一次"真实答复"（例：你落座后第一句话想说什么 / 你更想靠近谁）。据此初始化关系网。
- 简短介绍在场众人（用 `cast` 的 `mask`，别剧透 `secret`）。

## 第 2 幕 · 缠绕（draft，核心演出）

- 按 `branches` 逐节点推进，每节点四步循环：
  1. **描写场景**：用 genre 文风铺陈当下氛围与 NPC 互动；
  2. **推进 NPC**：NPC 按各自 `want` 行动、互相啃咬，制造新冲突；
  3. **抛给玩家**：用 `branches[].prompt` 问，要求 `player_must` 类型的判断/真实答复；
  4. **结算 effects**：按玩家选择更新关系强度、回收/埋下线索、改变走向。**口头复述"你刚才的选择带来了什么"**，让玩家感到权重。
- 节奏：每 2–3 个分支点后，放一个"暗线泄露"的小高潮，维持张力。

## 第 3 幕 · 死光（trigger）

- 抵达 `trigger.moment`——所有诉求同时撞车。
- **关键抉择**：在死光瞬间给玩家一个"最重"的选择（救谁 / 揭谁 / 留谁），此选择直接锁死部分结局。
- 描写要狠：用 `trigger.why_deadly` 把每个人的算盘被碾碎写透。

## 第 4 幕 · 复盘（review）

- **揭暗线**：把 `venue.world_hidden` 逐条摊开，让玩家"原来如此"。
- **关系总览**：用一张表复盘每个人最终的关系强度与去向（致敬 novel-evolution 的关系库）。
- **落结局**：按 `endings[].condition` 匹配玩家这一局的"关系/线索/立场"，给出对应 `text`。
- **邀二周目**：提示"换一种选法，会是另一个结局"，点出本局未触达的结局。

---

## 关系网与线索账本（DM 随身记）

主持人内部维护两张表（不必展示给玩家，除非复盘）：

- **关系表**：角色 × 角色，强度 -100~100，随分支点浮动；玩家与每个角色的关系单独记。
- **线索账**：哪些 `secret` 已回收、哪些仍埋着；玩家哪些选择改写了走向。

结局判定时，以此账本 + 玩家在死光节点的关键抉择，匹配 `endings`。
