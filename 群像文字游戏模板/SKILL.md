# 群像文字游戏模板

> 一场群像文，就是一场"局"。
> 别人写群像，是让你**看**六个人怎么在饭桌上撕。
> 这个模板，是让你**坐**到那张饭桌上去——你是第七个人，你的一句话、一个真实的选择，会真的改变谁先翻脸、谁最后离场。

## 它是什么

一个**元模板**（meta-template）。它本身不讲故事，它是一台"群像文 → 文字游戏"的**生成器**：

- 你给它一篇群像文（或一个点子），它吐出一个**具体可玩的游戏 skill**；
- 一台游戏 = 一个 `game-data.json`（角色卡 + 场域 + 死光节点 + 分支点 + 结局矩阵）+ 一份**可运行的 SKILL.md**；
- Agent 加载这份 SKILL.md 后，化身**主持人（DM）**，带玩家走完一局。

**核心契约**：玩家不是旁观者。玩家以"第七人"身份卷入同一事件，中途必须不断做出**判断**和给出**真实的自己的答复**，这些输入被主持人"记住"并实时改写关系网与剧情走向。

## 什么时候用

- 用户想把一个群像故事（饭局 / 家族聚会 / 董事会 / 婚礼 / 同学会…）做成**能玩**的东西；
- 用户要"按这个模板批量产出各种文字游戏 skill"——本模板就是那条生产线；
- 用户想做**沉浸式互动叙事 / 文字剧本杀 / 分支剧情**，且强调"玩家中途能干预剧情"。

## 与群像写作 skill 的关系

本模板是**引擎**，群像写作 skill 是**燃料**：

1. 先用群像写作 skill 把"群戏三要点 / 四要素 / 死光节点"打磨到位，产出一个有意思的群像文骨架；
2. 再把那个骨架喂给本模板的「实例化配方」，自动长成一个可玩的游戏 skill。

两者搭配，闭环成立：**写得好看 → 玩得带感**。

## 实例化配方（5 步把群像文变成游戏 skill）

> 完整字段定义见 `fixed/schema.md`，场景预设见 `fixed/genres.json`，主持人运行流见 `workflow/dm-runtime.md`。
> **🚨 沉浸式铁律 · 必须贯穿 5 步**：一切优化决策以"真实使用者中途会不会出戏"为唯一衡量标准。
> 详见 MEMORY.md「🎭 沉浸式体验铁律」。

**第 1 步 · 定场域（裹挟事件）**
选一个把所有人强行塞进同一时空的"事件"——一场饭局、一次家族春节、一场董事会。
一句话写清：*时间 / 地点 / 那件把所有人裹挟进来的事 / 玩家未必知道的"世界暗线"*。
**沉浸式要求**：场域必须有 1-2 个**身体动作锚点**（"筷子"、"酒杯"、"空调的嗡嗡声"），开场白用身体动作切入，不用"欢迎来到"这种系统语。

**第 2 步 · 立角色卡（各自诉求 + 秘密 + 与玩家关系）**
3–7 个角色，每人填：
- `want`：**各自的核心诉求**（群戏第一铁律——人人有私心）；
- `mask`：表面人设 / 伪装；
- `secret`：秘密 / 伏笔；
- `tie_to_player`：与"第七人"（玩家）的恩怨或羁绊；
- `arc`：弧光（表层住相 → 深层住相）。
**沉浸式要求**：每个角色的 `want` 必须**具体到一句话能说清**（"想表白"、"想借钱"、"想逃"），不要写"想解决某问题"这种抽象词——DM 要能拿这句话驱动 NPC 主动行动。

**第 3 步 · 设死光节点**
一句话写下**所有诉求同时撞车的那一刻**（例："A 突然举杯宣布：我要离开杭州"）。这是全剧最高压、最不可逆的引爆点。
**沉浸式要求**：死光时刻必须配套 `trigger.why_deadly`——把每个 NPC 的"诉求被碾碎的样子"写成一句具体的话（"B 表白的话全咽回去了"、"E 借钱的话说不出口了"），不能只是抽象的"目标冲突"。

**第 4 步 · 布分支点（玩家代理点）· 情境留白版**
列出 4–8 个玩家**必须表态**的节点。每点写清：
- 发生在第几幕
- **抛给玩家的情境**（NPC 的动作/眼神/话引入问题，**不**用"你怎么办"）
- 玩家被要求做的**真实答复**类型
- 不同答复如何改变**关系强度 / 线索回收 / 走向**

**沉浸式硬要求**（违反 = 破坏沉浸）：
- ❌ **不**给 ABCD 选项
- ❌ **不**列"帮 / 不帮"二选一
- ✅ 只抛情境 + 留白，等玩家用自己的话说
- ✅ DM 用 `parse_intent`（解析意图规则）替代 `match_choice`

**第 5 步 · 填结局矩阵 → 产出（沉浸式版）**
定义 3–5 种结局（基于关系强度、线索是否回收、玩家立场组合）。
**沉浸式要求**：结局文本必须是"揭幕式情绪收束"——把暗线揭出、关系总览、用一句身体动作/环境描写收尾；**不**是成就列表。

产出两份文件：
- `game-data.json`：以上全部结构化数据；
- `SKILL.md`：把 game-data 内联 + 写明本局的运行指令（直接复制 `实例/饭局文字游戏/SKILL.md` 改即可）。

**SKILL.md 自检清单**（生成后必查）：
- [ ] 顶部存档快速参考卡用的是 **沉浸式开场白模板**（"你又来到了这张桌子"），不是"输入 1-N"
- [ ] 附录 §1 提问模板的"红线"包含 ❌"不给 ABCD 选项"
- [ ] **不**在 SKILL.md 中向玩家解释 slot 号、JSON、schema、emoji
- [ ] 文风守则里加了**身体动作锚定句**（每 2-3 段穿插 1 个该 genre 的标志性意象）
- [ ] 复盘环节的模板是"揭幕式收束"，**不**是成就列表
- [ ] 跨会话开场白模板走"情绪接住三件套"

## 文件结构

```
群像文字游戏模板/
├── SKILL.md              ← 你正在读：元模板 + 实例化配方
├── README.md             ← 总览与速查
├── fixed/
│   ├── schema.md         ← 游戏数据 schema（每个字段的类型/含义/示例）
│   └── genres.json       ← 场景预设（饭局/春节/董事会/婚礼…）
├── workflow/
│   └── dm-runtime.md     ← 主持人(DM)运行流：布场→入局→缠绕→死光→复盘

    └── 饭局文字游戏/      ← 已产出的具体游戏 skill（可直接加载游玩）

        └── game-data.json
```

## 调用约定（Agent 怎么跑一局）

1. 加载目标游戏的 `SKILL.md`（它已内联 game-data 与运行指令）；
2. 严格按 `workflow/dm-runtime.md` 的四幕推进；
3. **把玩家当真实的人**：他的判断和真实答复要被"记住"，后续情节、NPC 态度、结局都受其牵引；
4. 世界独立于玩家运转——NPC 按自己的 `want` 行事，不为取悦玩家而存在；
5. 一局结束做"复盘"：揭暗线、亮关系总览、给结局、邀二周目。
